# Start here

You can explore MADAR without installing software or learning Git commands.

## What is this repository?

A **repository** holds source files, documentation, and a history of changes. The [README](../README.md) is its front page. A source repository is not the same as a deployed application.

1. Read the project overview and course list in the README.
2. Choose a guide from the [documentation index](README.md).
3. Select a directory or file to browse it. GitHub displays Markdown files as formatted documents.
4. Use the directory path at the top to navigate back.

**Code → Download ZIP** downloads a snapshot of the files. It does not start the application or include its complete change history. Interface labels and available actions may vary with account permissions and repository settings.

## Common GitHub terms

| Term | Meaning |
| --- | --- |
| Issue | A report or proposal that can be discussed and tracked |
| Branch | A separate line of work before changes are integrated |
| Commit | A recorded set of changes with a description |
| Pull request | A request to review and merge a branch's changes |
| Actions | Automated checks and their results |
| Release | A named version selected by the maintainer; not every change is a release |

## Report a problem

Issues are enabled. If you have repository access, choose **Issues → New issue** and use the relevant template. Explain what you did, what you expected, and what happened. The repository remains private while the requested public-access preparation is reviewed.

For learning-content corrections, include the course, lesson or question, and a source supporting the correction. Do not attach account information, real progress backups, or screenshots containing personal data. Follow [SECURITY](../SECURITY.md) for sensitive reports.

## Do I need to run the application?

No, if you only want to understand the project. For local development, continue to the [development guide](DEVELOPMENT.md).
